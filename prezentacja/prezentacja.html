02 / Problem i cel

Nie tylko „funkcja wywołuje siebie”

  • Każde wywołanie ma własne argumenty.
  • Rodzic czeka na wynik dziecka.
  • Baza zatrzymuje zejście, nie wszystkie powroty.

Odbiorca: student poznający rekurencję.

Stos ≠ drzewo

Stos: co jeszcze pracuje?
Drzewo: co zostało wywołane?

Cel: umieć przewidzieć następny krok na nowych danych.

Hanoi

n−1: from → aux
n:   from → to

M(n) = 2ⁿ − 1

05 / Struktury danych

Zdarzenie wykonania

type · id · parentId · depth
args · line · reason
locals / value / move

Unikatowe id wiąże ruch lub wynik
z konkretnym wywołaniem.

Stan odtwarzacza

  • Tablica stosu → push / pop
  • Map węzłów → wynik zostaje
  • A, B, C → tablice od dołu do góry
  • cursor → następne zdarzenie

Wejście: + ramka · Powrót: − ramka, + wynik w drzewie

depth korzenia = 0; maksymalny stos liczymy w ramkach, korzeń = 1.

09 / Wnioski i ograniczenia

Co pokazuje laboratorium?

  • Suma: Θ(n), stos Θ(log n)
  • Potęga zwykła: Θ(n + 1)
  • Potęga szybka: Θ(log n), n ≥ 2
  • Hanoi: Θ(2ⁿ), stos Θ(n + 1)

Mały stos nie oznacza małej liczby ruchów.

Uczciwe granice

Małe dane; ślad w pamięci.
Walidator i renderowanie liczone osobno.
Brak benchmarku czasu ściennego.

Wkład i źródła
